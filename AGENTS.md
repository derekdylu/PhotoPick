# AGENTS.md

PhotoPick: a macOS PySide6 app (plus a stdlib-only CLI) that finds orphaned RAW/JPG pairs and drags picked RAWs into Lightroom, with a Next.js landing site in `web/`.

User-facing docs: [README.md](README.md) (app, CLI, build, Gatekeeper fix) and [web/README.md](web/README.md) (site dev and deploy). Don't repeat them here.

## Layout

- `photopick/core/`: scanner, matcher, thumbnail cache. Keep it free of GUI imports; `rawpy` and `PIL` are imported lazily inside `thumbs.py` so the CLI runs on the standard library alone.
- `photopick/ui/`: PySide6 app. Entry point `photopick.ui.app:main`.
- `photopick.py`: CLI wrapper around `photopick.core`.
- `scripts/build_macos.sh`: builds `dist/PhotoPick.app` and `dist/PhotoPick-<version>.dmg` with PyInstaller + hdiutil.
- `web/`: Next.js 14 App Router site (English at `/`, Traditional Chinese at `/zh`, strings in `web/lib/i18n.ts`).

## Commands

App (Python 3.10+):

```bash
pip install -r requirements.txt
python -m photopick.ui.app                        # run the GUI from source
python photopick.py /path/to/photos               # CLI, dry-run
python3 -m compileall -q photopick photopick.py   # quick syntax check
./scripts/build_macos.sh                          # .app + .dmg (uses .venv-build/)
```

Web (run inside `web/`):

```bash
npm install
npm run dev     # http://localhost:3000
npm run lint
npm run build
```

There is no test suite and no CI. Validate app changes with `compileall` plus a CLI dry-run on a scratch folder; validate web changes with `npm run lint && npm run build`.

## Deploy and release

- Web: Vercel Git integration, Root Directory `web`. A push to `main` deploys production; there is no GitHub Actions workflow. Check the Vercel deployment status after pushing.
- Env: `NEXT_PUBLIC_SITE_URL` (see `web/.env.example`). Local values go in `web/.env.local`, which is gitignored.
- App: no automated release. Build locally with `./scripts/build_macos.sh`; `.dmg` files are meant for GitHub Releases.
- The version comes from `pyproject.toml`. Bump both `[project].version` and `[tool.briefcase].version`; the build script reads the first.

## Conventions

- Work on `main` and push directly; there are no PR branches.
- Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `style:`, optional scope such as `feat(web):`.
- Keep the web copy bilingual: any user-facing string change in `web/` needs both the English and `zh` entries.

## Safety

- The GUI's "Move to Trash" uses `send2trash`. Keep it that way; never switch the GUI to a permanent delete.
- The CLI's `--execute` calls `Path.unlink()`, which is a permanent delete. Never run it against real photo folders; test on a scratch copy.
- Don't commit `web/.vercel/`, `.env*` files other than `web/.env.example`, or build output (`build/`, `dist/`, `.venv-build/`, `logs/`).

## Gotchas

- `PhotoPick.spec` is generated by PyInstaller on every build and is gitignored (`*.spec`). Change build options in `scripts/build_macos.sh`, not in the spec.
- `.gitignore` ignores `lib/` globally with an exception for `web/lib/`. Keep that exception or the i18n strings disappear from git.
- Builds are ad-hoc signed and not notarized, so macOS reports a fresh download as "damaged". The fix is in the README's "First launch" section.
- Thumbnails are cached in `~/Library/Caches/PhotoPick/thumbs/`; clear it when a thumbnail change seems to have no effect.
